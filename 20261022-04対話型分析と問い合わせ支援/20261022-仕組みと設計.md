# 対話型分析と問い合わせ支援

普段の言葉による質問から集計結果を作る機能と、業務資料を探して回答を支援する機能。

## 利用者と課題

分析担当、業務担当、問い合わせ対応担当が利用する仕組み。

数値の確認には問い合わせ文の作成が必要で、資料を使った回答には必要な文書を探す時間がかかる。質問から必要な情報へ進める入口を用意する。

## 主な機能

| 機能 | 内容 |
|---|---|
| 質問からの集計 | 質問内容と指標の定義をもとに、データへの問い合わせ文を組み立てる。 |
| 結果の返却 | 集計結果を表計算資料や文章にまとめる。 |
| 資料検索による回答支援 | 関連する業務資料を探し、回答に必要な文脈を与える。 |
| 用語管理 | 業務用語の定義を保存し、問い合わせ文の生成に渡す。 |

## 処理の流れ

質問 → 用語・関連資料の参照 → 集計または回答案の生成 → 結果整理 → 利用者への返却

この流れは説明用の要約。実際の処理では入力確認、権限確認、例外時の対応などが加わる。

## 技術と役割

| 技術 | 役割 |
|---|---|
| Python（データ処理に使う言語） | 質問処理、集計、資料作成 |
| FastAPI（処理を外部から呼び出す窓口を作る道具） | 質問の受付 |
| RAG（資料を検索してから回答を作る方法） | 関連資料による回答支援 |
| LlamaIndex（資料の整理と検索を支える道具） | 資料の取り込みと検索 |
| PostgreSQL（表形式のデータ保存の仕組み） | 分析対象の保存 |

## 設計上の見どころ

### 数値集計と資料回答を区別

数字を求める質問と、手順を求める質問で必要な情報源が異なる。

### 用語の意味を補う

同じ言葉の意味や指標の定義を、問い合わせ文の生成前に補う。

### 表と説明を併せて返す

数値を再利用できる形で渡し、読み取れることを文章で説明する。
