# 旧通販の顧客向け機能

購入申込、会員向け画面、定期契約の変更、継続・解約の案内を提供する顧客向けの仕組み。

## 利用者と課題

購入者、定期契約の利用者が利用する仕組み。

広告から購入した利用者が、購入後も自分の契約を確認し、配送日や内容を変更できる必要があった。案内から契約変更までがつながる顧客向け画面を提供する。

## 主な機能

| 機能 | 内容 |
|---|---|
| 購入申込 | 商品紹介から申込、確認、完了までを案内する。 |
| 会員向け画面 | 契約内容、購入履歴、配送に関する情報を確認する。 |
| 契約変更 | 配送日、数量、選択項目、休止・再開などを扱う。 |
| 継続・解約の案内 | 利用者の状況に応じた案内と契約手続きを提供する。 |

## 処理の流れ

商品紹介 → 購入申込 → 確認 → 申込完了 → 会員向け画面 → 契約変更

この流れは説明用の要約。実際の処理では入力確認、権限確認、例外時の対応などが加わる。

## 技術と役割

| 技術 | 役割 |
|---|---|
| PHP（ウェブ処理を書く言語） | 画面に応じた処理と契約操作 |
| EC-CUBE（通販サイトの土台となるソフト）の旧世代 | 購入・会員管理の基本機能 |
| Smarty（画面のひな形を作る仕組み） | 表示と処理の分担 |
| JavaScript（画面上の動きを作る言語） | 入力補助と対話形式の案内 |

## 設計上の見どころ

### 購入後も含めた画面設計

売って終わりにせず、配送や契約の変更まで一続きの利用体験にする。

### 契約状態と表示の整合

変更できる項目、受付できる時点、表示する案内を契約状態に合わせる。

### 新基盤へ渡す仕様の整理

旧画面の分岐や例外を、新しい基盤で確認するための資料にする。
