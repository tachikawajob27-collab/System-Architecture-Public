# 担当分担型の業務自動化

業務ごとの人工知能の担当と手順書を用意し、報告や下書き、計算、定期的な確認を支える仕組み。

## 利用者と課題

管理担当、業務担当、意思決定者が利用する仕組み。

日々の報告、資料探し、確認事項の整理、下書き作成が複数の情報源にまたがる。担当する役割と作業手順を分け、繰り返し行える形にする。

## 主な機能

| 機能 | 内容 |
|---|---|
| 役割ごとの指示書 | 分析、在庫、商品開発など、仕事ごとに参照先と作業範囲を定める。 |
| 作業手順書 | 報告や資料作成の手順と、確認事項をまとめる。 |
| 定期的な実行 | 日次・週次などの確認や報告を決まった時点で行う。 |
| 計算処理の分離 | 必要数量や費用などの計算はプログラムに任せる。 |

## 処理の流れ

情報収集 → 業務担当へ振り分け → 手順に沿って処理 → 計算・根拠確認 → 報告や下書き → 人が判断

この流れは説明用の要約。実際の処理では入力確認、権限確認、例外時の対応などが加わる。

## 技術と役割

| 技術 | 役割 |
|---|---|
| Markdown（見出しや表を書ける文書形式） | 役割定義と作業手順書 |
| JavaScript（処理を書く言語） | 外部情報の取得補助と計算 |
| Python（データ処理に使う言語） | 集計と資料作成の補助 |
| MCP（人工知能が外部の道具を使うための共通の接続方式） | 業務資料やデータの参照 |

## 設計上の見どころ

### 役割と手順を分ける

担当の目的と、個別作業の詳しい手順を分離して管理する。

### 判断と計算を分ける

数値は計算処理で求め、判断材料と確認事項を文章にまとめる。

### 情報源の責任を分ける

手順、業務ルール、数値の正本を区別して参照する。

## 紹介する範囲

実際の担当者名、社内の意思決定経路、会社資料の保存場所、実行予定、取引先への指示は収録していない。

個人ごとの設計・実装・運用の分担や成果の数値は、元資料だけでは確定できないため断定していない。
