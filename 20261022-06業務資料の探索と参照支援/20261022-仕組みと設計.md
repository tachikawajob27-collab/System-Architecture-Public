# 業務資料の探索と参照支援

社内のどこに必要な資料があるかを案内し、業務別の参照方法と読み取り手順を整理した仕組み。

## 利用者と課題

業務担当、分析担当、人工知能を業務に使う担当が利用する仕組み。

資料が複数の保管先に分かれ、文書名だけでは最新の情報や数値の正本を見つけにくい。大きな表を一度に読み取ると必要な行が抜けることもある。

## 主な機能

| 機能 | 内容 |
|---|---|
| 資料の地図 | 目的別に情報源と参照方法を整理する。 |
| 業務別の案内 | 分析・在庫・予定確認など、仕事に応じた探し方を示す。 |
| 必要範囲の読み取り | 大きな表から必要な行・列だけを取得する。 |
| 参照結果の確認 | 記載と実際の資料が食い違う場合に確認・修正する。 |

## 処理の流れ

知りたいこと → 業務別の案内 → 正本となる資料 → 必要範囲の取得 → 根拠を確認 → 回答

この流れは説明用の要約。実際の処理では入力確認、権限確認、例外時の対応などが加わる。

## 技術と役割

| 技術 | 役割 |
|---|---|
| Markdown（見出しや表を書ける文書形式） | 資料案内と業務ルール |
| Python（データ処理に使う言語） | 表の範囲を指定した読み取り |
| API（別の仕組みから機能を呼び出す窓口） | 資料の取得 |
| OAuth（利用者が許可した権限で接続する方式） | 読み取りに必要な認可 |

## 設計上の見どころ

### 資料そのものと案内を分ける

正本を複製せず、必要な情報にたどり着く手順を管理する。

### 全体取得より範囲指定

必要な行・列に絞って、大きな表の読み落としを減らす。

### 読み取り専用の用途

参照のための道具に、不要な書き込み機能を持たせない。
